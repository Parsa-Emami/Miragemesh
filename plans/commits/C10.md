## Required negative cases

- Missing prerequisites, malformed fixtures or unavailable required providers produce an explicit error rather than placeholder success.
- Repeat after restart and verify the declared invariant and documented recovery outcome.
- No egress by default
- Owner-approved C10 scope: an unsigned document, a wrong-key signature, a tampered payload and a re-serialized payload are rejected with typed errors.
- A stale revision, an expired document, a not-yet-valid document and a redefined revision are rejected with typed errors, and no rejection replaces the active configuration.
- Seventeen malformed desired-state documents are rejected with typed errors: malformed JSON, unknown member, duplicated member, wrong schema version, non-positive revision, impossible timestamp, inverted validity window, out-of-range settings and an oversized payload.
- The active configuration is process state in C10: a restarted service owns no remembered applied revision, so the documented recovery outcome is that the operator re-applies the latest signed desired state. The durable applied revision and the crash convergence of an apply belong to C11.
- No egress by default: the desired-state service performs no socket operation; its signing key is trusted local configuration and is independent from the mTLS CA and CRL material.
- No key material, public or private, is committed to the repository or to the C10 fixtures; the tests sign with one ephemeral in-memory Ed25519 key pair.
- Owner review round one on `a444f05` found three defects and one policy wording, all resolved: the result of `Apply` no longer aliases the stored active configuration, the verification key is copied into service-owned memory at construction, the validity window is rechecked under the state lock at acceptance time, and the accepted range of the settings is explicit deployment policy instead of a hard-coded product limit.
- Owner follow-up review on `2a2d15c` found two further P2 findings, both resolved: the evidence and session handoff now state the proposed-policy status of the event-count ceilings instead of calling them the documented product profile, and the documented batch-to-spool constraint is enforced as a document invariant, so a document whose event batch exceeds its spool is rejected with a typed error.
