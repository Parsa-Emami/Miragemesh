# داوری سخت‌گیرانه MirageMesh

تاریخ: ۱۴ آبان ۱۴۰۵، برابر با ۵ نوامبر ۲۰۲۶. مبنای بررسی: سورس `d4dc9c8`، نسخهٔ منتشرشدهٔ `v0.0.1` و مسیرهای عمومی که در همین بررسی در مرورگر مشاهده شدند.

## نتیجه

**خیر؛ MirageMesh هنوز همهٔ شرایط یک وب‌اپ امنیتی عمومی و بالغ در کلاس جهانی را ندارد.** هستهٔ محلی آن نقاط قوت قابل‌بررسی دارد و نسخهٔ متن‌باز منتشر شده است، اما تکمیل C01 تا C40 به معنی برابری با محصولات جاافتاده، آمادگی میزبانی چندکاربره یا اثبات تقاضای بازار نیست.

مهم‌ترین کمبود حتی ظاهری نیست: مسیر فعلی پذیرش mTLS و سناریوی کامل، با harness آزمون اثبات شده است. هنوز باید نصب سنسور مستقل، جمع‌آوری پیوسته، راه‌اندازی توسط کاربر عادی و مشاهدهٔ رویداد واقعیِ همان کاربر، خارج از fixtureهای آزمون، به‌صورت یک مسیر عملیاتی مستند و آزموده عرضه شود. صرف اجرای `npm start` این کار را انجام نمی‌دهد.

GitHub Pages برای معرفی، توزیع و نمایش نمونه مناسب است؛ موتور Go و پردازش امنیتی روی آن اجرا نمی‌شوند. رابط جدید این مرز را آشکار نشان می‌دهد.

## معماری پیشنهادی

برای این ابعاد، یک برنامهٔ ماژولار Go با مرز روشن بین دامنه، کاربرد، API و آداپتورها، به‌همراه React و API هم‌مبدأ انتخاب مناسبی است. میکروسرویس و دیتابیس توزیع‌شده در این مرحله توجیه اندازه‌گیری‌شده ندارند. آداپتور فعلی تک‌میزبانه باید در محدودهٔ آزموده‌شده باقی بماند؛ رشد ظرفیت نیازمند سنجش تازه است.

هویت کاربران و اعلان‌ها به‌صورت آداپتور اختیاری طراحی شوند. ورود ابری اجباری نشود. برای استفادهٔ محلی تک‌کاربره نیازی به قابلیت‌های SaaS نیست، اما عرضهٔ وب‌اپ تیمی از راه دور بدون مجوزهای سمت سرور قابل‌قبول نیست.

تغییر Schema، migration، `.env` و Dockerfile همچنان خارج از مجوز فعلی است. اگر توسعه‌ای واقعاً به آن نیاز داشت، باید همان مانع دقیق ثبت شود.

## بازطراحی U01

رابط همهٔ صفحه‌های موجود از الگوها و اجزای shadcn/ui معرفی‌شده در 21st، با مجوز MIT و منبع دقیق، بازسازی می‌شود: پوستهٔ اپلیکیشن، ناوبری کناری، تم روشن/تیره، جست‌وجوی صفحه‌ها، جدول‌ها، فرم‌ها، وضعیت‌ها و نمایش خطا. ظاهر و ترکیب‌ها برای MirageMesh تطبیق داده شده‌اند؛ وابستگی آنلاین اجباری به 21st وجود ندارد.

نمای عمومی دادهٔ مصنوعیِ برچسب‌خورده دارد و دادهٔ امنیتی واقعی را نمایش نمی‌دهد. نمای محلی از endpointهای موجود، با اعتبارسنجی پاسخ، خلاصهٔ واقعی می‌خواند. این تغییرات معادل پیاده‌سازی Backendهای پیشنهادی جدول بالا نیست.

ترتیب منطقی ادامه: **U01 → اولین کار واقعی کاربر → سنسور/Collector پیوسته → تحقیقات و اعلان → مرز تیمی در صورت نیاز → سلامت/بازیابی/ظرفیت → آزمون مستقل و انتشار نسخهٔ جدید.**
